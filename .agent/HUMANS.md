# .agent/ — A Note for Human Readers

This directory is **AI agent infrastructure**. It is not intended for human
developers to read or maintain directly.

## What is this?

This repository is built through agentic engineering — AI agents write the
code, the owner provides direction and design guardrails. The `.agent/`
directory is the operational scaffolding that makes this work: rules, plans,
session memory, specialist reviewer definitions, and a learning loop that
improves governance over time. It keeps agentic-first engineering knowledge in
plain text so agents from different vendors can collaborate, learn, and adapt
without relying on private platform memory.

The Practice lineage here was transplanted from the Oak Open Curriculum
Ecosystem on 2026-09-12. The manifest and the owner's rulings are recorded at
[`docs/explorations/2026-09-12-oce-practice-lineage-transplant.md`](../docs/explorations/2026-09-12-oce-practice-lineage-transplant.md).

## Why are there also .claude/, .cursor/, .codex/, .agents/ directories?

This repo uses a three-layer model:

1. **`.agent/`** — canonical content (rules, skills, sub-agents)
2. **`.claude/`, `.cursor/`, `.codex/`, `.agents/`, `.github/agents/`** — thin
   platform adapters that point back to `.agent/`, regenerated by
   `pnpm portability:fix`
3. **`CLAUDE.md`, `AGENTS.md`** — entry points that platforms read

The adapters exist so the same rules and capabilities work across different
AI tooling. If you see similar-looking files in `.claude/rules/` and
`.agent/rules/`, the `.claude/` version is a one-line pointer to the canonical
`.agent/` version.

## Can I safely ignore this directory?

Mostly. None of these files change how the site builds, runs, or is tested.
The quality gates (`pnpm check`, `pnpm test`, `pnpm type-check`) are what
enforce code quality — though some gates do police `.agent/` content itself
(markdown lint, portability and sub-agent validators), so a `.agent/` change
can turn `pnpm check` red.
