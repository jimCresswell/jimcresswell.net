## Goal

The alignment `practice-alignment-by-class` reached on 2026-10-05 (776 shared paths identical
across the two estates, 9 differing by the family placeholders alone, 44 differing as the
contextual layer) is readable at any later moment by one command, and the one open correctness

workspace fails closed, checked by the conformance validator rather than claimed by a hook comment.

## Mechanism

Two slices, each one pull request per estate, the same bytes but for the package scope and the
skill prefix.

1. **The fail-closed property.** Every `pnpm --filter` alias in
   `.agent/family/typescript/practice-operations.json` and in each estate's root manifest carries
   `--fail-if-no-match` (today `agent-tools:build`, `agent-tools:prevent-accidental-major-version`,
   `agent-tools:secret-scan`, `subagents:check` and `agent-tools:context-cost` lack it while the
   hook comments say every agent-tools alias carries it). The conformance validator gains a
   manifest self-check that reads the property over every filtered script body, so a future alias
   cannot join the manifest bare; the hook comments then claim what the validator proves. This is
   the remainder both code landings named (322, #354) and Copilot's finding on the final sibling
   tip, true in both estates; the class, not the instance, as the round-four lesson says.
2. **The drift reading as an instrument.** The byte proof run by hand at the finish (a scratch
   script reading two trees with `git ls-tree` and `git cat-file` over the family and doctrine
   prefixes, counting shared, identical, placeholder-only and differing paths) becomes a tracked
   agent-tools command taking this checkout at a ref and a sibling checkout at a ref, with the
   scopes and prefixes as arguments so the file names neither estate. The finish's partition is
   recorded beside it as the baseline (the 44 differing paths by name), so a run reads movement
   against the finish and not against nothing. It runs on demand and at the coordination fold's
   records pass; it is not a CI gate, since the sibling checkout is a machine fact.

What this node hands the extraction's definition: the three sets, named and reproducible. It
does not say what extraction means; the owner's three open questions (the strategy choice on
language-agnostic doctrine, how the instruments reach a non-TypeScript host, the conformance
corpus) stay with the archived sketch `practice-language-separation`.

## Acceptance criteria (each with a proof)

1. Every filtered alias in the family manifest and both root manifests carries
   `--fail-if-no-match`. Proof: `validate-family-conformance` OK in both estates with the
   manifest self-check live, and a unit case for a bare alias that reads as a drift.
2. The drift command exists in both estates as the same bytes and reproduces the finish's
   partition when run at the two merged tips (`SHA:d3647a9d` in jimcresswell.net, `SHA:ef42bd11f`
   in OCE): 829 shared, 776 identical, 9 placeholder-only, 44 differing. Proof: the command's
   output at those refs, pasted on the pull request.
3. The baseline is a tracked file the command reads, and a run after any later change to a
   shared path shows the path as moved against it. Proof: one deliberate edit on a branch, the
   command's diff against the baseline naming it, the edit discarded.

authoring; four pull-request lifecycles, mostly waiting. A slice whose authoring passes its
